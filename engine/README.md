# Off-Hire Proof — rules engine

`index.mjs` is a dependency-free ES module. No imports, no I/O, no clock. The caller supplies
`today` as an ISO date string, so the same inputs always give the same outputs.

Surface is frozen in [`API.md`](./API.md) and is not changed here:
`offHireWindow`, `chargedToDate`, `offHireRecord`, `parseISO`, `addDays`, `formatPence`.

## What it does

Arithmetic on the hire terms the user typed in — on-hire date, daily or weekly charging, rate in
pence, minimum chargeable periods, days of off-hire notice, and whether Saturdays and Sundays are
charged days. From those it returns:

- `nextChargeDate` / `nextChargePence` — when the next charging period begins and what it costs.
- `callByDate` / `daysUntilCallBy` — the last day to give notice before that period begins.
  `daysUntilCallBy` is signed; a negative number is simply a count of days, and the interface
  describes it.
- `minimumEndsDate` / `minimumNotYetMet` — the last day of the minimum hire period, and whether it
  still has days to run after today.
- `periodsCharged` / `chargedToDatePence` — periods from the on-hire date to today inclusive.
- `basis` — one plain-English line per input actually used, so the interface can show its working.

`offHireRecord(fields)` turns an off-hire call into copy-ready plain text: hire company, machine,
asset number, when it was off-hired, the reference the hire desk gave, who was spoken to, notes. It
computes nothing and invents nothing; `offHiredAt` is copied through exactly as entered.

## Decisions a reader will want stated

- **A week is seven calendar days from the on-hire date**, not a Monday-to-Sunday week.
- **`chargesWeekends: false` with daily charging** means only Monday to Friday are charged days: the
  day count, the minimum period and the next charge date all skip Saturday and Sunday.
- **`chargesWeekends: false` with weekly charging changes no figure.** The seven-day period still
  runs from the on-hire date and the whole weekly rate falls due. The flag is reported in `basis`
  so the user can see it was read and had no effect.
- **A period is counted the moment it begins.** Part-week rebates (the 60%/80% tables some hire
  companies publish) differ between companies and are not computed.
- **Both readings, always.** Where the notice period and the minimum hire period give different
  call-by dates, `callByDate` is the earlier of the readings that apply today and `basis` carries
  both, labelled. The minimum reading stops entering the comparison once the minimum has been
  served, and `basis` says so in that case rather than dropping the line.
- **Bank holidays are not modelled.** No public holiday calendar is in the engine. Where the
  call-by date lands on a Saturday or Sunday, `basis` states the day and points at the hire
  company's opening hours.
- **Bad input throws `TypeError`** rather than returning a confident wrong number: non-ISO dates,
  float pence, `minimumPeriods` under 1, negative `noticeDays`, a non-boolean weekend flag.

## What it deliberately does not do

- No verdict, in any field or any sentence. There is no field whose name judges the user's
  position; the test suite asserts the exact output shape against `API.md` and fails if a
  verdict-shaped field name appears.
- No statement about anyone's position in law, and no statutory input at all. These are commercial
  terms the user entered.
- No contact with a hire company, ever. The user makes the call and records it here.
- No floats for money. Integer pence throughout, and `formatPence` is the only producer of a
  currency string.
- No `Date` object, timezone or clock anywhere across the boundary. Civil dates only, as written on
  a delivery note.

## Running the tests

```
node --test engine/test.mjs
```

`test-vectors.json` holds 70 cases, each with an `id`, a `why` naming the edge it pins, the inputs
and the expected outputs — including boundary triples (day before, day of, day after), month ends,
leap days, century non-leap years, `noticeDays: 0`, notice longer than the period, weekend-excluded
charging, `today` before the on-hire date, daily charging across 31 days, and nine invalid-input
cases. The expected values were generated by a separate brute-force reference implementation
(day-by-day loops) and then checked against this engine's closed-form arithmetic, so the two agree
independently. Any later port loads the same file.

The reference generator is kept at `engine/tools/make-vectors.mjs`. It shares no code with
`index.mjs` and regenerates `test-vectors.json` byte for byte:

```
node engine/tools/make-vectors.mjs engine/test-vectors.json
```
